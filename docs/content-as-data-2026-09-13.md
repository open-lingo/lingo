# Content as data — lesson JSON pipeline (2026-09-13)

**Owner:** Spencer (decisions) · **Status:** IN TREE, uncommitted · **Ledger:** `handoff-2026-09-11-mobile-qa.md`

## Why

The cold open on an iPhone 15 Pro Max was 14.4 s to Home text. Measured on the
device (probe + chunk marks), not guessed:

| phase | before | now |
|---|---|---|
| shell paint | 0.24 s | 0.24 s |
| `mockLessons` chunk eval (41 × JA `compileModule` at import) | 3.3 s | **0 — content is JSON, loaded per module** |
| Home render task (239k `localStorage.getItem` of the 200 KB SRS store; iOS WebKit ≈ 30 µs/read) | 7.3 s | 0.5 s (`getSRSStore` validates once per task) |
| Home text | 14.4 s | 4.2 s measured with fix 4 alone; JSON pipeline pending phone measure |

Duolingo's own write-up says the same thing we found: content is data fetched
per lesson and cached on device, startup work moves to after the home screen
paints, launch metadata loads only the current section.

## Shape

- **Emitter** `npm run content:emit` (runs as a vitest file so it gets the
  `@/` aliases and the eager registry; gated by `CONTENT_EMIT=1`). Evaluates
  every course once — JA IR through `compileModule`, ES/FR factories, KO
  tables — and writes `src/pub/content/v1/`:
  `manifest.json` (mutable) · `<lang>/<moduleId>.<hash10>.json` `{ lessons }` ·
  `<lang>/_extra.<hash>.json` (lessons in no course-map module) ·
  `ja/mined.<hash>.json` (sentence-miner index). 13 MB total, gitignored,
  regenerated by `predev` / `prebuild` / `prebuild:native` / `preflight`.
- **Registry** `lesson/data/lessonRegistry.ts` — the mutable table every
  lesson read goes through, with a revision counter.
  `lessonRegistry.eager.ts` is the old static import block; only tests and
  the emitter see it, via `virtual:lesson-registry-bootstrap` (plugin in
  `vite.config.ts`; empty module in every real build).
- **Loader** `lesson/data/contentLoader.ts` — `ensureLessonLoaded(id)` loads
  the lesson's module and every earlier module of its course (review tails,
  grammar pools and the dynamic review prefix mine earlier lessons);
  `ensureCourseLoaded`, `ensureAllContentLoaded`, `ensureMinedSentencesLoaded`.
  Native reads the files from the app bundle (`capacitor://localhost/content/…`);
  web reads them through CloudFront + the service worker (hashed → CacheFirst,
  manifest → NetworkFirst).
- **React** `lesson/data/useLessonContent.ts` — `useLessonReady`,
  `useCourseReady`, `useAllContentReady`, `useContentRevision`. `LessonPage`
  is gated; Home's flashcard summary and the course map rebuild on revision.
  `home/useNextLessonWarm.ts` loads the next lesson's module and its first
  clips once Home is idle ("current lesson + 1").

## Rules

1. Never import a curriculum module from app code. Content reaches the app
   only through the registry.
2. Anything memoised over "all lessons" must key on `getContentRevision()`.
3. Sync reads (`getMockLessonContent`) may return null until the module is
   loaded — gate the surface with a hook, never busy-wait.
4. Keep local caches small: next lesson's module + ~60 clips. Whole-module
   audio packs remain opt-in (`mobile-offline-oss-scoping-2026-08-06.md` §T3/T4).

## Committed generated data (per language, not gitignored)

Small JSON files, each with a Node-only `*.eager.ts` aggregator and a
`*.generated.test.ts` stale guard, read by `courseAtoms.ts`/`placementBank.ts`
instead of importing/globbing every `curriculum/m*.ts` (whole lesson bodies):
`es|fr/curriculum/atoms.generated.json` ← `atomsAggregate.eager.ts`, and
`es|fr/curriculum/placement.generated.json` ← `placementAggregate.eager.ts`
(`PlacementItem.build`, a closure, is materialized to a plain `step` at emit
time and rewrapped in `() => step` by the consumer).

## Follow-ups

- ES/FR course *structure* still comes from `es|fr/curriculum/index.ts`, which
  imports every module's TS — their content is in the bundle twice (JS +
  JSON). Emit a structure file and drop the JS imports.
- OTA content: the manifest is already versioned; a native build could fetch
  a newer manifest from the CDN and prefer CDN files over bundled ones.
- Course-map vocab samples load the whole course; a lightweight vocab index
  per module would keep that page to one small file.
