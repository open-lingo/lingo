## 1. Shared recipe — insert one lesson into a shipped IR module

Precedent: **F18, `ja-m29-neo-14`** (`docs/ja-freq-gap-plan-2026-08-26.md`
§2.6, lines 327–421 for the fully worked beat sequence; `docs/handoff-2026-08-26-freq-wave.md`
lines ~150–185 for the actual build log — note the plan's proposed id
`ja-m29-neo-10` **collided** with an existing lesson, so it shipped as
`ja-m29-neo-14`; **id ≠ position is established precedent**, don't assume the
suffix means order).

1. **Add the lesson block** to `curriculum/ir/mN.ir.yaml` — new `- id:
   mN-neo-<X>` under `lessons:`, `role: teaching`, `introduces: [...]`,
   beats per the template (§2). Position as the LAST teaching lesson before
   the module's final review (`mN-neo-review-3`/`-r3`), so
   `mN-neo-challenge` stays last (inv 25 — enforced by `moduleCompiler`
   detecting a review lesson by the *absence* of a challenge beat).
2. **Compile:** `node scripts/compile-ir.mjs mN` — reads the yaml, writes
   `mN.ir.json`. The app imports JSON, never YAML.
3. **Wire into the module's TS list:** `curriculum/mN-neo.ts`, add
   `byId("ja-mN-neo-<X>")` into `MN_NEO_LESSONS` at the same position (see
   `m29-neo.ts:53–67` — the array literally *is* the shipped order).
4. **Add the map tile:** `src/shared/domain/mockCourse.ts`, module's
   `lessons:` array — `{ id: "ja-mN-neo-<X>", title: "...", status:
   "available" as const }` at the matching position (`mockCourse.ts:1091`
   for m29's F18 entry). Skipping this is the #1 named B067 trap — the
   lesson compiles but is unreachable.
5. **Atom rows:** every pack-word below has a `courseAtoms.ts` row except
   `かたづける` (pack 12). Update `fromModule` to the teaching module.
   **Leave `introducedByLessonId` UNSET** — a static value suppresses the
   module-fallback unlock path forever, the B068 mechanism
   (`docs/backlog/items.yaml` B067 fix, constraint 3). Leave `blocked` as-is
   unless you have a genuinely better image.
6. **New atoms** (only `かたづける` needs this): add a `courseAtoms.ts` row
   (`kind`, `pos`, `conjugation` for verbs — check `conjugationTables.ts`
   too) before referencing it in IR (`irAtomRegistration.test.ts` is the
   reverse arrow that catches an IR-only atom with no row).
7. **TTS:** `node scripts/emit-tts-deck.mjs` (whole-deck, additive) then
   `npm run module-gate -- mN-neo` (§3) to see which new sentences lack a
   clip. The emitter is regex-based and silently skips unmatched shapes —
   "wrote=0" isn't proof of success, the gate's coverage diff is. Full
   generation chain (`emit-tts-deck.mjs` → `lingo-data`'s
   `pipeline.tts.generate --lang ja --provider edge` → `gen_dialogue_voices`
   → `emit_manifest` → `upload` → copy manifest into
   `src/shared/tts/manifests/`) is a real network batch job — confirm with
   the coordinator before running it.

## 2. Template (`docs/ja-freq-gap-plan-2026-08-26.md` §2.2)

**Template A — vocab-pack re-cement** (use for every pack below; Templates B
function-word and C paired-contrast, §2.3–2.4, don't apply — all 7 packs are
concrete nouns/verbs/adjectives with honest images or carriers). 14 authored
beats: 1 `rule` (a NEW variant of the module's own grammar point, stated
through the pack's words) → 3 `sentence build` → 1 `particle-cloze` (new
word as answer, distractors all taught atoms) → 3 more `sentence build` → 1
`listening-comp` (reuse an authored sentence, zero new TTS) → 1 `sentence
listening` → 1 `kanji` (review-tier word only) → 1 `sentence translate` (at
most one) → 1 `dialogue` closer (2–3 lines, 1 question) → 1 `challenge` (≥3
grammar points, shape unseen in this module) → `reviewPool` of 8–10
prior-module nouns the closing `match_pairs` actually spends.

## 3. Gates — run these, in order, before calling a pack done

```
npm run module-gate -- mN-neo          # vitest (module's own test file) + TTS coverage diff + tsc --noEmit, one summary
npx vitest run --project curriculum src/features/languages/ja/__tests__/atomExposureAudit.test.ts   # never-graded/never-touched ratchets — must not go UP
npx vitest run --project curriculum src/features/languages/frequencyAtoms.test.ts                    # freqRank/unlock-module stability (only matters if you re-home a `future`-tagged atom)
npx vitest run --project curriculum src/features/languages/ja/__tests__/moduleConformance.test.ts    # inv 25 (15-lesson cap, challenge-last), other structural invariants
npx vitest run --project curriculum src/features/lesson/data/kanaWordIntroOrder.test.ts              # kana-before-word ordering
npx vitest run --project curriculum src/features/languages/ja/__tests__/irAtomRegistration.test.ts   # only if you registered a new atom (pack 12's かたづける)
npx tsc --noEmit
```

`npm run test:run` runs the full CI split (`curriculum` + `app` projects) for
a final pass; `--project curriculum` while iterating (`CLAUDE.md:296–305`).

handoff's standing constraints.
