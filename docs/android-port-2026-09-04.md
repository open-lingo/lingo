# Android port — sideload debug APK (2026-09-04)

Purpose: a sideloadable APK for a tester (Maddie) that hits prod exactly the
way the iOS build does. Not a Play build; no release keystore.

## What exists

- `android/` — generated by `npx cap add android` (Capacitor 8). Two hand edits:
  - `app/src/main/AndroidManifest.xml`: `VIEW` intent-filter for scheme
    `com.linguiversal.app` (Auth0 redirect back into the app; mirrors
    `CFBundleURLSchemes` on iOS).
  - `local.properties` (gitignored) = `sdk.dir=~/Library/Android/sdk`.
- `capacitor.config.ts`: `android.backgroundColor`; scheme left at the default
  `https`, so the webview origin is **`https://localhost`** (iOS is
  `capacitor://localhost`).
- Speech: `@capacitor-community/speech-recognition` on Android. The iOS Swift
  plugin was written to that package's contract, so the only JS change is a
  plugin-name switch — `nativeSpeechPluginName()` in
  `src/shared/speech/useNativeSpeechRecognition.ts`. On iOS the package is
  skipped by `cap sync` (not SPM-compatible; `Package.swift` unchanged) and the
  Swift plugin keeps answering.

## Toolchain (this Mac, no sudo, no Android Studio)

```
brew install openjdk@21                      # temurin cask needs sudo; this doesn't
brew install --cask android-commandlinetools
export JAVA_HOME=/opt/homebrew/opt/openjdk@21/libexec/openjdk.jdk/Contents/Home
export ANDROID_HOME=$HOME/Library/Android/sdk ANDROID_SDK_ROOT=$ANDROID_HOME
sdkmanager --sdk_root=$ANDROID_HOME "platform-tools" "platforms;android-35" \
  "build-tools;35.0.0" "emulator" "system-images;android-35;google_apis;arm64-v8a" \
  "cmdline-tools;latest"
```
⚠️ Use `$ANDROID_HOME/cmdline-tools/latest/bin/avdmanager` (the in-SDK copy).
The Homebrew copy cannot see the system images and fails with a bare `null`.

## Build

```
npm run build:native            # needs .env.native — same file as iOS
npx cap sync android
cd android && ./gradlew assembleDebug
# → android/app/build/outputs/apk/debug/app-debug.apk (~37 MB)
```

## Release build

Per `docs/android-play-store-2026-09-13.md` §"Code delta" (signing + version
derivation landed there; keystore generation and Play upload are still
Spencer's steps). Not run by this repo pass — no keystore exists yet.

```
export LINGO_UPLOAD_KEYSTORE=/path/outside/repo/upload.jks
export LINGO_UPLOAD_KEYSTORE_PASSWORD=...
export LINGO_UPLOAD_KEY_ALIAS=...
export LINGO_UPLOAD_KEY_PASSWORD=...
# or drop the same 4 keys in android/keystore.properties (gitignored, local-only)

npm run build:native && npx cap sync android
(cd android && ./gradlew bundleRelease)
# → android/app/build/outputs/bundle/release/app-release.aab
```

`versionCode`/`versionName` are derived from the repo-root `package.json`
`version` field (`versionCode = major*10000 + minor*100 + patch`); override
with `LINGO_ANDROID_VERSION_CODE` for CI. Without the 4 signing env vars (or
`android/keystore.properties`) set, `bundleRelease` still configures and
runs, it just produces an **unsigned** AAB — Play will reject that, so the
vars are required before the actual upload build.

Reminder: `applicationId` (`com.linguiversal.app`) is **permanent** once the
first AAB is uploaded to Play Console — Play never allows changing it on an
existing listing, only retiring it and publishing a new one under a new
package name.

## Config outside the repo (required, per platform origin)

Same shape as the iOS entries in `handoff-2026-09-01-native-auth-ftue.md`:

- Auth0 client `bIKQzPiAKK6RVApeWjiV6tbseSX9Qqjc` ("Open Lingo Native"):
  `allowed_origins` and `web_origins` += `https://localhost`. Callback and
  logout URLs are the custom-scheme URL and are already present (same on both
  platforms).
- lingo-core Lambda (us-west-1, profile `lingo`): `CORS_ORIGINS` += `https://localhost`.
  Terraform ignores this variable, so it is a live edit (see the 09-01 handoff).

Blast radius of `https://localhost` in CORS: a page served from a local HTTPS
dev server could make credentialed cross-origin calls, but every API route
still requires a valid Auth0 bearer token, so this widens nothing that the
`capacitor://localhost` entry did not already widen.

## Status 2026-09-04 (end of day)

Verified on the API 35 emulator (`maddie`), driven over CDP, against prod:

- Auth0 login round-trip: Universal Login in a Chrome custom tab → sign-up →
  `com.linguiversal.app://…/callback` → `appUrlOpen` → signed in. Both origin
  entries above are live (Auth0 native client + lingo-core `CORS_ORIGINS`).
- API calls to the prod Lambda succeed (CORS header confirmed on the wire).
- Home + vertical map render; `ko-m1-intro` plays to completion with 0 JS
  errors; TTS decodes (16 clips in `ko-m1-v-1`).
- Speech: community plugin available, RECORD_AUDIO prompt works, native
  session starts. Two plugin behaviours needed hook-side fixes in
  `useNativeSpeechRecognition.ts` (tests in the sibling `.test.ts`):
  1. **Recognizer dies without a `stopped` event.** `onError` calls
     `stopListening()` and rejects a call that already resolved; nothing
     reaches JS. Fix: a 300 ms `isListening()` watchdog (Android only — the
     Swift plugin has no `isListening`). Measured: UI leaves "Listening…"
     ≤300 ms after the native death, hint = no-speech.
  2. **`stop()` never resolves its call** (Java `stop` returns after
     `stopListening()`; only an exception settles it). Manual tap-to-stop
     hung on "Stop recording". Fix: bounded wait (`STOP_SETTLE_MS` = 750).
     Measured: idle in ~765 ms, retry works.
- Not verified: speech with a REAL microphone (emulator runs `-no-audio`, so
  every session ends in the native-error path). First real-device tap is the
  tester's.

Findings that are not Android-specific (unfixed, logged here so they are not
re-discovered):

- FTUE: if the first username save reports failure the user IS registered;
  every retry gets 409 "User already registered", shown as "Username already
  taken", and the page never advances.
- `public/feature-flags.json` never ships — Vite `publicDir` is `src/pub`.
- Capacitor logs a safe-area CSS injection null error at Android launch.
- lingo-ops Lambda has no native origins in its CORS list (not needed by the
  app today).

## Sideload instructions for the tester

Settings → Apps → Special app access → Install unknown apps → allow for the
app used to open the file (Files / Chrome / Drive). Open `app-debug.apk`, tap
Install. A debug build cannot update a Play-installed app and vice versa.
