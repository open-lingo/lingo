# JLPT N4 course tier — scoping

2026-07-16. Scopes the next course tier for the **ja** course: N4 grammar + vocab as a new
module set, a new transit-map ZONE, the lesson-type gaps N4 forces, the infra to extend, and
a wave build plan. Read-only recon; nothing here is built yet. Decision-oriented — one
recommendation per open question, alternatives noted inline. Owner calls collected at the end.

**Where ja is today (verified):** m1–m2 kana, m3–m27 grammar+themed ≈ JLPT N5 / CEFR A1–A2
complete. 23 step types (`src/features/lesson/types.ts`); ~521 live course atoms across m3–m27
(`courseAtoms.ts`, 749 total − 218 `future` − 10 sidequest); N5 kanji ladder live from m8
(display-only, furigana unlock+2). N4 modules would number **m28+** (course ceiling is m27
everywhere: `mockCourse.ts`, `tiers.ts`, `courseAtoms.ts`, `levelBands.ts`).

## 1. N4 curriculum scope → module set

### What N4 actually adds over N5

| Bucket | N5 had | N4 adds |
|---|---|---|
| Register | polite (ます/です) only | **plain form mastery** (dict/ない/た/て plain) as a productive register + casual↔polite switching |
| Clauses | single-clause sentences | **relative (noun-modifying) clauses**; 〜という; 〜し; 〜ので/〜のに |
| Conditionals | — | **たら・と・ば・なら** (four, contrastive) + 〜たほうがいい |
| Verb voice/mood | plain vocab forms | **potential** (られる/できる), **passive** (られる), **causative** (させる), causative-passive (intro), **volitional** (よう＋と思う) |
| Give/receive | — | **あげる・くれる・もらう** + て-form giving (〜てあげる/くれる/もらう) |
| Experience/manner | — | 〜たことがある, 〜ながら, 〜すぎる, 〜やすい/にくい, 〜方, 〜つもり/予定 |
| Evidentials | — | 〜そう (looks/hearsay), 〜みたい, 〜らしい |
| Politeness | です/ます | **keigo intro** (尊敬語/謙譲語: おV-になる/おV-する, いらっしゃる, 召し上がる, 伺う) |
| Vocab | ~660 N5 words | **+700–800** new words |
| Kanji | ~100 (all live by m22) | **+170** new (cumulative ~300) |

### Proposed module set — 12 modules (m28–m39), one ZONE 2

Grammar is sequenced so each anchor's prerequisite ships earlier. **Plain form first** (it
gates relative clauses, conditionals, たことがある, casual dialogue — almost everything N4).

| # | Theme | Grammar anchor (prereq) | Vocab domain (~new atoms) |
|---|---|---|---|
| m28 | Plain & casual | plain form dict/ない/た/て + casual register | casual verbs, friends, slang-lite (~45) |
| m29 | Describing in detail | noun-modifying (relative) clauses; 〜という | objects/qualities, descriptions (~50) |
| m30 | If & when | たら / と conditionals | daily situations, weather, directions (~45) |
| m31 | Advice & conditions | ば / なら + 〜たほうがいい / 〜ので | problems, health, advice (~45) |
| m32 | I can do it | potential form (られる/できる) | skills, work tasks, ability (~50) |
| m33 | Giving & receiving | あげる/くれる/もらう + て-giving | gifts, favors, social exchange (~45) |
| m34 | Experiences | 〜たことがある / 〜ながら / 〜し | hobbies, travel, life events (~50) |
| m35 | Plans & intentions | volitional よう(と思う) / つもり / 予定 | goals, future, scheduling (~45) |
| m36 | How it seems | 〜そう / 〜みたい / 〜らしい / 〜すぎる | opinions, feelings, judgement (~50) |
| m37 | Passive voice | passive られる | news-lite, society, events (~50) |
| m38 | Causative | causative させる (+ caus-passive intro) | work, school, obligation (~45) |
| m39 | Polite society | keigo intro 尊敬語/謙譲語 + おV-になる/する | service, business, formal (~45) |

**~560 core new atoms**; the remaining ~150–240 lower-frequency N4 words fold into reading
passages + review tails rather than dedicated teach cards (mirrors how N5 backlog sits in the
218 `future` atoms — a pre-attributed pool already exists to draw from).

### Density check (sampled real numbers)

| Metric | N5 themed module (m8–m27) | N4 proposal |
|---|---|---|
| Content lessons / module | ~15 (7 topic pairs + story) + 2 SRS reviews | **keep 15 + 2** |
| New atoms / module | 13–39 (avg ~20; m8=39, m5=26, m17=26) | **~45–50** (upper end of N5's band) |
| Steps / lesson | 6–9, hard cap 25 (es spine + ja files) | keep |

The one real tension: **700–800 words at literal N5 density (~20/atom module) = ~35 modules**,
which is a second course, not "the next module set." Recommendation packs N4 into **12 denser
modules (~45–50 atoms each)** — defensible because reading speed is established (kana/kanji
ladder done) and it stays inside N5's observed 13–39 range. *Alternative:* keep ~20/module and
split into **N4a/N4b (~20 modules, two zones)** shipped as two waves — truest density, double
the map + authoring surface.

### What N4 demands that N5 never needed

- **Verb-form transformation at scale** — potential/passive/causative/plain each need
  *produce the transformed form*, not *recognize a vocab surface*. This is the one genuinely new
  interaction (see §3); the conjugation ENGINE exists but only backs the standalone trainer.
- **Register switching** — every plain↔polite pair doubles the surface inventory and needs an
  explicit "say this casually / say this politely" drill.
- **Longer listening** — 5–8-turn dialogues with register variation (N5 topped out at 2–4 turns);
  `dialogue_listen` already scales to this (see §3).
- **Kanji toward reading recall** — N4 vocab is markedly more kanji-dense; the display-only
  ladder may need a productive reading step (owner call, §3d).

## 2. Transit map — the N4 zone

### How the map works today (verified in `TransitLearnPage.tsx`)

- **One main line**, single color `--tmc-line-main` (`#e5493a` / dark `#ff6a5b`). Modules render
  as stations along an S-curve (`LEVELS`/`LEVEL_SEQ`/`RUNS`); `buildLayout()` (line 218) lays
  them out straight from `getMockCourse()` module data. Per-module `accent` gradients exist in
  `mockCourse.ts` but the map does **not** use them for the rail — the rail is one hue.
- **Zones are geometric thirds, hardcoded to exactly 3** (`buildLayout` line 484:
  `stations.length >= 9 && zoneLabels.length === 3` → splits *all* stations into 3 equal x-bands).
  Labels/numerals come from `transitStrings.ts` (`zones: ["ZONE 1 · はじまり", "ZONE 2 · 日常",
  "ZONE 3 · 出発"]`). **So today's ZONE 1/2/3 are visual thirds of the single N5 line — not
  tiers.** Appending 12 N4 stations would silently rebalance those three bands across N5+N4 and
  destroy the semantics. **This is the load-bearing seam.**
- **Scenery** (`makeSkyline`, line 532) is procedural parallax off layout geometry: far hills ×2,
  mid + near building rows, 2 mountains, torii + pagoda, blue-noise stars, drifting clouds,
  panel-pinned moon. Landmark set is per-language (`landmark: "ja" | "ko"`). Mountain/torii/pagoda
  x-positions are **keyed off `layout.zones`** (lines 587, 594, 699–700) — so a zone-model change
  ripples into scenery placement for free.
- **Locked** stations/spurs already render **dashed** (`dashed: a.status === "locked"`,
  `.tmc-row-future` dashed rail in CSS) — the visual-gating primitive exists.

### Recommendation: N4 = ZONE 2 as a distinct scenery+color band beyond an interchange

Re-key the zone model from "geometric thirds" to **tier-grouped bands**, then give the N4 band
its own palette and scene. Concretely:

| Seam | Change | File |
|---|---|---|
| Zone boundaries | Replace the `=== 3` thirds split with **tier-derived bands**: reuse `groupModulesByLevel()` (already groups modules into fluency sections) so zones = fluency groups and scale to any module count. N5 collapses to its bands, N4 (m28–m39) becomes its own band(s). | `TransitLearnPage.tsx` buildLayout 483–502; `courseLevels.ts` |
| Interchange | Mark **m27 as the transfer station** (terminus of N5) and m28 as the N4 line entry — reuse existing `interchange`/`terminal` station flags. | buildLayout stations loop |
| Line color | Add `--tmc-line-n4` and switch the rail hue past the transfer (or render N4 as a **second line**). Recommend a cool hue (teal/indigo) vs N5's warm red — instant "different network." | `transitLearnPage.css` `.tmc-root` vars |
| Zone strings | Extend `zones`/`numerals` arrays past 3 (e.g. add `ZONE 4 · 旅` / `ZONE 5 · 敬語`); today's array-length-3 guard must be relaxed. | `transitStrings.ts`; `transitStrings.test.ts` |
| Scenery shift | New palette + landmark set for the N4 band (see below), placed off the new tier bands. | `makeSkyline` + `SkylineArt` |
| Visual gate | N4 stations render **dashed/locked** until m27 clears — reuse existing locked treatment. No new primitive. | already supported |

### Scenery direction (pick one)

**Recommend: city → countryside → mountains ("leaving the starter city").** N5 is the lit city
(towers, torii, pagoda, Fuji). The N4 band swaps to **rural rail — rice fields, a shinkansen
sweeping past, temples climbing into mountains**. Why it reads as "next tier" at a glance: it's a
literal *scene change*, not a re-tint — you've physically left the beginner city and are
travelling. It reuses the existing layered-parallax system almost verbatim (hills → paddies,
building rows → sparser countryside, the 2 mountains grow, torii/pagoda → a mountain temple + a
shinkansen sprite), so it's a palette + landmark swap, not new geometry.

- *Alt A — Night city:* same skyline, night palette. Weak: dark-mode already renders the city at
  night (`.tmc-night` stars/moon), so it wouldn't read as a new tier for dark-theme users.
- *Alt B — Kyoto temples:* strong "advanced Japan" read but a bigger bespoke-landmark lift than
  reusing the hills/mountains you already have.

**Zone gating:** yes — the N4 band should render dashed/greyed beyond the m27 transfer until it
unlocks, matching current locked-module dashing. Reads as "a future line on the map you'll
transfer onto," which is exactly the tier metaphor.

## 3. Lesson-type gap analysis

Existing 23 types (`STEP_TYPE_ORDER`), walked against N4. Prefer reuse/parametrization; a genuinely
new type ≈ 1–2 days incl. factory + tests (the `agreement_cloze` precedent). Note: `fill_blank`
exists but is **unused everywhere**, and `agreement_cloze` ships es-only — both are candidate
vehicles for reuse.

| Candidate | Verdict | Why | Effort |
|---|---|---|---|
| **conjugation_cloze** — produce/pick a conjugated form in sentence context ("私は日本語が___[potential]") | **ACCEPT — build it** | The single highest-value N4 type. No existing type drills a *conjugated verb form in a sentence*: `particle_cloze` is particles only; `fill_blank` is generic free-text with no form logic. The **conjugation engine already backs it** — `FORM_TO_TILES`, `generateFormationDistractors`, `COMBO_MAP` (`ja/conjugation/`) generate the tiles + plausible wrong forms. Wire engine → step factory. Could physically reuse the unused `fill_blank` shell, but a purpose-built type carries the form metadata cleanly. | ~2–3 days (engine wiring > a plain new type) |
| **sentence_transform** — polite↔plain, active→passive rewrite | **REUSE (parametrize)** | A transformation is a `build_sentence` where the prompt states the operation and tiles assemble the target. Add optional `sourceSentence` + `transformLabel` to `build_sentence` rather than a new type — the source shows above, tiles below, existing grading unchanged. | ~1 day (param + renderer tweak) |
| **longer multi-turn dialogue comprehension** | **REUSE — author only** | `dialogue_listen` already takes unbounded `lines[]`, N questions, `format: "narrative"`, and two-voice `VoiceColor`. N4 just needs longer authored instances + register variation. No code. | 0 (content) |
| **kanji_reading** — given kanji word, produce/pick reading (or reverse) | **CONDITIONAL** | Only worth building **if kanji goes productive in N4**; today the ladder is deliberately display-only (`applyKanjiSurfaces`, render-gated). If yes: a dedicated type that respects the furigana window + `N5_KANJI`/`N4_KANJI` schedule. If the owner keeps kanji recognition-only, a plain `multiple_choice` ("which reading is 食べる?") covers the light case. | ~1–2 days *if* built (owner call §5) |
| **register_choice MCQ** — pick the situationally-appropriate politeness level | **REUSE** | This is a tagged `multiple_choice` (exactly how `self_explanation_mcq` is a tagged MCQ). Optionally add a `register` tag for analytics/feedback copy; no new interaction. | ~0.5 day if tagged, else 0 |

**Net new code:** **1 definite new step type** (`conjugation_cloze`, engine-backed), **1
conditional** (`kanji_reading`, only if kanji goes productive), **1 parametrization**
(`build_sentence` transform). Everything else N4 needs is authoring on existing types.

## 5. Build plan — wave method adapted to N4

Same shape that shipped es A1 (spine spec → exemplar → N parallel agents on whole files, zero
conflicts). Two differences: N4 needs **code prerequisites** (the new step type + map zone) done
*before* the content wave, and a **grammar-points** artifact.

| # | Session | Output | Human vs agent | Rough effort |
|---|---|---|---|---|
| 1 | **Spine spec** | `docs/n4-course-spine-2026-07-16.md`: per-module vocab pre-allocation (surface\|gloss\|kind), grammar anchor + sequencing, register/keigo depth, kanji schedule, `n4-grammar-points.json` skeleton | **Human decides** module count, theme order, grammar sequencing, the ~700-word source list, register policy; agent drafts the allocation | 1 session |
| 2 | **Step-type code** | `conjugation_cloze` (factory + renderer + engine wiring + tests); `build_sentence` transform param; `kanji_reading` *if* approved | Human approves the interaction; agent implements TDD | 2–3 sessions |
| 3 | **Exemplar module** | Fully authored **m28** as the pattern all agents copy | Human reviews the exemplar; agent authors | 1 session |
| 4 | **Content wave** | m29–m39 by **N parallel agents, one module per agent, whole-file ownership** (no shared-file conflicts) | Agent-derivable from spine + exemplar; human spot-checks | 1–2 sessions wall-clock |
| 5 | **QA drive** | qaCatalog coverage for new types, density lints, ratchet checks (passive→retrieval, listening sentence-level, match-grid floors), placement/level-band extension | Agent runs the lint/test suite; human triages | 1 session |
| 6 | **Map ZONE 2** | Zone-model rework (tier bands), N4 scenery + landmark set, line color, strings, visual gating | Human picks scenery direction; agent implements | 1–2 sessions |
| 7 | **Kanji + TTS** | `N4_KANJI` catalog + `applyKanjiSurfaces` extension; TTS emit batch | Agent-derivable; human confirms readings | 1 session + 1 emit run |

**Human-decided:** module count, zone scenery direction, ship-behind-flag y/n, grammar
sequencing, the N4 word list, keigo depth, one-line vs second-line on the map.
**Agent-derivable:** all per-module lesson authoring, distractors, atom registration, review
tails, TTS keys, kanji entries from the schedule.

**Total effort:** ≈ **1.3–1.5× es A1 content** + **~4–6 days of new code** (step type + map zone
+ kanji extension). Realistically **~9–11 focused sessions** (1 spine · 3 step-code · 1 exemplar ·
1–2 wave · 1 QA · 1–2 map · 1 kanji/TTS), ~2–3 weeks at the es cadence.
