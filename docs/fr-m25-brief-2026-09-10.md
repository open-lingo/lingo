## 2. Module thesis (design authority for this dispatch)

**m25 promotes `qui` from three modules of silent chrome to real, graded
content.** The learner has SEEN `"c'est qui ?"` three times already — in
m12, m17, and m21 — every time as a wrong answer they were meant to reject
without understanding why. This module cashes that debt: `qui` slots into
the exact wh-in-situ question shape the course has used since m5
(`"tu vas où ?"`), asking and answering who something or someone is/belongs
to, recombining the cast and the possession-`de` frame (m3/m22) the learner
already owns.

The teaching claim to state explicitly in the module header (paste-ready):
"You've seen «c'est qui ?» before — three times, always as the WRONG
answer in a dialogue. Here's why it looked wrong: you didn't know «qui»
yet. Same question-word-at-the-end trick as «tu vas où ?» — now you can
finally say it back."

**Two beats, taught in this order:**
1. **`"c'est qui ?"` — the productive, fully graded construction (L1–L4,
   L6–L7).** Debut via the bridge card above, quoting one of the three
   existing foils verbatim (recommend `m21.ts:1111`, the most recent).
   Answer with the already-taught `"c'est [Name]"` pattern (m7's own
   `"c'est Léa"` precedent, `m7.ts:1430`) across the full consonant-onset-
   safe cast. Recombine with possession-`de` (m3/m22: `"c'est le chat de
   Léa"` → `"c'est qui, le chat ?"` / `"c'est le chat de Léa"`).
2. **`"qui est-ce ?"` — a RECOGNITION-ONLY frozen alternate (L5).** Same
   meaning, different (inversion-shaped) word order. Explicitly taught as
   "another way people ask the same thing — you'll recognize it, you don't
   need to produce it," never generalized into a productive inversion
   rule, never a `speaking` or `build` target (§2.1 below states why).

### 2.1 Design decision: `"qui est-ce ?"` ships recognition-only, not
productive

This is a genuine judgment call, recorded with reasoning per the
escalation-filter norm, not silently resolved. `"qui est-ce ?"` is
structurally inversion-shaped (`est-ce`, echoing the `est-il`/`a-t-il`/
`qu'est-ce que` family) — the SAME class of syntax `m19.ts`'s own header
(read directly, decision 4) records as deliberately avoided
(`"qu'est-ce que"` verified registered nowhere, sim questions built with
plain word order instead), and which every FR module since m2 has
declined to teach generatively (grepped: zero occurrences of
`est-il`/`est-elle`/`a-t-il`/`va-t-il`/`est-ce que` anywhere in m1–m24
outside m2's own untaught tease line and brief prose). Teaching
`"qui est-ce ?"` as a PRODUCTIVE pattern would imply the learner can now
form other inversions by analogy — false, and exactly the mis-signal the
course has avoided six times running. Teaching it as a closed, frozen,
recognition-only alternate (same class as `FR_NPC_FORMULAS`'s glossed
service phrases, though NOT registered in that specific allowlist since it
IS a real graded-for-recognition atom, not an ungraded NPC formula) gets
the task's requested phrase into the module honestly without opening the
inversion gate. **Decision: `"qui est-ce ?"` is never a `speaking`,
`build`, or productive `cloze` target anywhere in m25** — recognition only
(`word_map` and/or `listening_comprehension`, meaning-matched, never
production-graded).

**Explicitly OUT OF SCOPE for m25** (state these, don't silently omit —
each is a real future candidate, not a rejected idea):
- **Relative `qui`** (e.g. "l'ami qui habite à Paris") — a different
  syntactic function (clause-embedding relative pronoun, not an
  interrogative), needing its own grammar machine the course has never
  built. The task's own framing asks to keep this module to the question
  word only; this line makes that scope boundary explicit and load-
  bearing, not a simplification.
- **Genuine productive inversion syntax** (`est-il`, `a-t-il`,
  `qu'est-ce que`) — still blocked course-wide (§2.1); `"qui est-ce ?"`
  ships as one frozen recognition-only exception, not a door-opener.
- Être-aux passé composé extension (arriver/partir/rester, §1.3) —
  available, priced, and handed to m26+.
- Partitives, `vous`, daily-routine reflexives (§1.4–§1.6) — all still
  genuinely blocked, unchanged from m24's assessment.
- d'-elision fix (§1.7) — m25 does not depend on it; flagged once more for
  the coordinator.

## 5. Homophone / liaison risks

- **`qui` is a short bare token (3 normalized chars)** — falls in the
  "short-token" class `frSpeechMinimalPairs.test.ts`'s course-wide census
  already flags as the LARGEST false-positive category (27 of 60 hits,
  per `docs/fr-speech-minimal-pairs-2026-09-10.md`). **`qui` never appears
  as an isolated, bare-word graded target anywhere in this module** — it
  is always embedded inside the full `"c'est qui ?"` sentence (mirrors
  m24's own `jus`-is-3-chars finding: safe when embedded, risky only in
  isolation). This is a design constraint for the drafting agent, stated
  explicitly, not left implicit.
- **`qui` vs `oui` is a plausible same-lesson confusion pair, NOT
  currently exercised** — both are short, single-syllable, vowel-adjacent
  words already in active rotation (`oui`/`non` since m1). No content
  proposed in this module pairs `qui` and `oui` as sibling speaking
  targets or same-lesson MCQ distractors (deliberately avoided by
  construction, §4) — but flagged here as the concrete instance of the
  short-token risk class, not a generic warning. If a drafting agent finds
  a natural reason to introduce `oui` as a distractor near `qui` content,
  re-check against `frSpeechMinimalPairs.test.ts`'s live matcher before
  shipping rather than assuming the embedding-safety finding above
  generalizes to that specific pairing.
- **No elision, no liaison, no gender/number agreement anywhere in this
  module's new content** — `qui` is invariant (no gender, no number, no
  elided form — it never contracts to `qu'` the way `que` does), and
  `"c'est qui ?"` / `"qui est-ce ?"` are both fixed strings with no moving
