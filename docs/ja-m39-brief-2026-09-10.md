## 0. What m39 teaches (from spine-n4.md, corrected below)

- **のに** "even though" — MINIMAL PAIR of ので (m16): same shape (nominalizer
  の, owned since m15), opposite job. Carries emotional colour (complaint/
  disappointment/reproach) — cue this explicitly on every production prompt;
  a neutral のに does not exist. **spiralWith: m16** (ので) — this field is
  MISSING from the spine's spec block but thr-n4's "CROSS-TIER DEEPENS" list
  names ので as one of seven N5 items requiring a cross-tier back-reference;
  I am recording the resolution here so you don't have to re-derive it.
- **〜ても** concession — て(m8) + も(m3), both owned; form is free, only
  meaning is new.
- **〜でも** on nouns; 疑問詞+でも/も as a CLOSED SET (なんでも/だれでも/
  だれも〜ない). Do NOT reuse courseAtoms id `"demo"` (kana でも, "but",
  discourse conjunction, fromModule "future") — that is a different word.
  Concessive でも/ても is attached morphology: treat as IR-local
  `grammarPointId`s only (same treatment as m38's te-shimau/chau), not a
  standalone vocab row.
- **〜し** listing reasons, "and what's more" implicature (やすいし、おいしいし).
  **⚠ HOMOGRAPH RISK (new finding, not previously documented anywhere in the
  repo):** courseAtoms already registers `id: "shi"` (kana し, kanji 四,
  "four", fromModule m13, blocked:true). `moduleCompiler.ts`'s `exercised()`
  tokenizes every sentence against the WHOLE course's atom registry and
  auto-feeds bare kana matches into `exercisedAtomKanas`, which drives FSRS
  Track A grading. Only one positional exception exists today (さん honorific
  vs 三 numeral, fixed for an identical past bug — see moduleCompiler.ts's
  comment near `exercised()`). No し exception exists yet. **This is a
  should-fix-alongside-authoring engineering task, NOT a hard blocker** — it
  doesn't break gates, tests, or rendering, only SRS-attribution accuracy (a
  learner producing 四 could silently credit the し-reason-particle card or
  vice versa). Add a second positional exception in `exercised()` (mirror the
  さん/三 pattern: kanji context disambiguates 四 from bare listing-し) as
  part of this module's PR, or file it explicitly as a follow-up ticket if
  you judge it out of scope — do not ship silently unaware of it.
- **⟳ deepen of m16's connective family** (から/ので/けど).

**why (spine's own words):** "The connective module N5 could not finish. m16
owned から/ので/けど; のに is ので's contrast partner and could only be
introduced pairwise once ので was old — which is now. ても sits here rather
than with the conditionals on purpose: it is semantically a CONCESSIVE, and
adding a fifth '-if' form beside たら/と/ば/なら would manufacture exactly
the N-way cross-association the conditional split exists to prevent."

**Disambiguation note for later (m48):** m48 teaches a DIFFERENT のに sense
("for the purpose of", きるのにべんり) — same string, disambiguated by what
follows. Don't preempt it; m39's のに stays purely concessive.

## 2. Shared recipe for a new N4 module (files → compile → register → gate)

Follow m38 as the structural template throughout
(`src/features/languages/ja/curriculum/ir/m38.ir.yaml`,
`.../curriculum/m38-neo.ts`,
`.../curriculum/__tests__/m38-neo.test.ts`). In order:

1. **Author the IR yaml**: `src/features/languages/ja/curriculum/ir/m39.ir.yaml`.
   Frontmatter: `module: m39`, `title`, `register`,
   `priorNeoModules: [m3..m38]`, `priorGrammarPoints: [...]` (copy m38's
   81-item list verbatim, it's cumulative — every N5+N4 grammar point taught
   so far), `notes:` (prose — record your spiralWith/homograph/carrier-vocab
   decisions here, matching m38's `notes:` block style, so the next reader
   doesn't have to re-derive them from this brief), `grammarPoints:` (new
   IR-local ids per §3 below — per inv 42, genuinely NEW N4-tier grammar
   points may freely invent new ids; do not force them into
   `n5-grammar-points.json`), `newAtoms:` (per §1 above — kana/kanji/gloss/
   shortGloss/imageable/kind/freqRank), `lessons:` (12 entries per §4 below).
2. **Compile**: `node scripts/compile-ir.mjs m39` → produces
   `ir/m39.ir.json`. `priorVocab` is computed automatically from
   `priorNeoModules`; do not hand-author it.
3. **Wrapper file**: `src/features/languages/ja/curriculum/m39-neo.ts` — copy
   m38-neo.ts's shape exactly (import `compileModule`, import the compiled
   json, `byId()` helper, export `M39_NEO_LESSONS` array in lesson order:
   1,2,3,review-1,5,6,7,review-2,9,10,review-3,challenge). Do NOT hand-edit
   lesson content here.
4. **Register the module** (5 touch points, all required):
   - `src/features/languages/ja/curriculum/taughtVocab.ts`: add
     `import m39Ir from "./ir/m39.ir.json"` and `m39: m39Ir` to
     `IR_BY_MODULE` (currently spans m6-m38).
   - `src/features/languages/ja/frequencyAtoms.ts`: bump
     `JA_FREQ_LAST_MODULE` from `38` to `39`. Enforced by
     `src/features/languages/frequencyAtoms.test.ts`'s "tracks the last
     live content module" test, which derives `lastLive` from
     `jaModule.curriculum` (→ `mockCourse.ts`) — will fail if you add m39
     to mockCourse.ts without this bump.
   - `src/shared/domain/mockCourse.ts`: append a new module-index entry to
     the n4 array, immediately after m38's entry (right before the array's
     closing `],` / `sideQuests,`). Shape: `{id: "m39", title, eyebrow:
     "Module 39 · JLPT N4", summary, tier: "n4", lessons: [{id, title,
     status: "available" as const}] (12 entries, ids `ja-m39-neo-<n>`),
     accent: {from, to}}` (pick a new accent pair, distinct from m38's
     `#0ea5e9`/`#0369a1`).
   - `src/features/languages/ja/mockLessons.ts` (or wherever
     `M38_NEO_LESSONS` is imported/spread today — grep for it): add
     `import { M39_NEO_LESSONS } from ".../m39-neo"` and spread into the
     lessons-by-id map.
   - New courseAtoms rows: register each genuinely-new atom from §1 in
     `src/features/languages/ja/courseAtoms.ts` with `fromModule: "m39"`
     (fields: id, kana, kanji?, romaji, meaningEn, shortGloss?, emoji?,
     freqRank?, fromModule, introducedByLessonId?, kind, pos,
     conjugation?). For the 3 existing blocked stub rows (kitanai, taihen,
     tsumaranai) flip `blocked` off and set `fromModule`/
     `introducedByLessonId` to point at m39 instead of creating new ids.
5. **Test file**: `src/features/languages/ja/curriculum/__tests__/
   m39-neo.test.ts` — copy m38-neo.test.ts's scaffolding: import every
   `M{N}_NEO_LESSONS` from m3 through m38 (for `priorLessons`), call
   `registerJaModuleContentLints("m39")` +
   `registerModuleBarGuards({moduleLabel: "m39-neo", lessons:
   M39_NEO_LESSONS, priorModules: [...m1..m38], priorLessons: [...],
   canon: COURSE_CANON, minLessons: 12, maxLessons: 15,
   requireChallengeLast: true, requireReviewCount: 3, requireImageFirst:
   true})`. Add your own bespoke ratchets for m39's headline pedagogical

6. **Gate, in order** (`npm run module-gate -- m39`, per
   `scripts/module-gate.mjs`):

   2. `node scripts/emit-tts-deck.mjs` regenerate + coverage diff against

   3. `npx tsc --noEmit --incremental`.
   4. Optional `MODULE_GATE_CAPTURE=1 npm run module-gate -- m39
