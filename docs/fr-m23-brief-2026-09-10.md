## 1. Theme verification (re-verified in code today, not inherited)

The task names six candidates to weigh: partitives (du/de la/des), `vous`
forms, être-auxiliary passé composé beyond aller/venir, time-telling, a
lexicon module, `on` as subject, `qui` as a question word. Each re-checked
directly against the shipped course, today:

### 1.1 Partitives (du/de la/des) — REJECTED, still blocked

`getFrRealFormLexicon()` (`moduleBarGuards.ts:108`) builds the course's
"every real word we know" set from atom surfaces + `FR_FUNCTION_WORDS` +
derived elided-clitic forms. Partitive articles need mass-noun vocabulary
(bread, water, cheese, coffee-as-substance vs. coffee-as-drink-order) that
does not exist in the atom registry — a grep across `m1.ts`–`m22.ts` for
any atom tagged as a mass/uncountable noun returns nothing; every food/drink
atom shipped so far (`café`, m6; the currency/shopping nouns, m12) is used
countably. A partitives module is therefore not a grammar-only beat — it is
a grammar beat gated behind an unbuilt vocabulary set, exactly the kind of
undercosted candidate m22's own brief flagged and rejected for the same
reason. Still rejected for m23: no new mass-noun atoms were added between
m22 and now, and authoring a partitives module would require inventing that
vocabulary INSIDE the same module (breaking the ≤10–12 atom ceiling on a
single already-new-content beat) or deferring it another cycle. Recorded as
a still-open candidate for whichever future module first ships mass-noun
food vocabulary (a lexicon module, §1.5, would be the natural place to seed
it).

### 1.2 `vous` forms — REJECTED, still blocked, would be the 11th decline

`FR_FUNCTION_WORDS` (`moduleBarGuards.ts`) lists `vous` as CHROME ONLY —
authorized for closed-class use (politeness formulas, m2's own tease lines)
but never as taught, conjugated content. Playbook §6 still defers it
explicitly: "`getConjugationGridConfig("fr")`, nous/vous/ils rows, and the
ES-style conjugation checkpoint law (~m11). Until then verbs are CHUNKS (je
vais / tu vas / on va precedent)." No conjugation-grid infrastructure has

helper). Every prior brief from m17 on has weighed `vous` and declined it
for the identical reason; m23 would be the module that makes it declined a
sixth+ time in a row. Still rejected — this is an infrastructure gap, not a
content judgment call, and nothing closed the gap this cycle.

### 1.3 Être-auxiliary passé composé beyond aller/venir — REJECTED

m19 shipped «aller + infinitif» (near future); m20 shipped «venir de +
infinitif» (recent past) — both auxiliary-chunk constructions, not a
generalized passé composé. Extending to genuine être-auxiliary compound
past (arriver/partir/rester + past participle with gender/number
agreement) would need: (a) new verb atoms for arriver/partir/rester
(unregistered — confirmed by grep, no atom with those surfaces exists
anywhere in `m1.ts`–`m22.ts`), (b) past-participle agreement machinery
that does not exist (the course's only prior "passé composé"-shaped
content is m16/m17's «il est déjà allé au parc» — a single memorized
recall chunk built on the ALREADY-taught aller+past-participle pattern,
not a generalized rule), and (c) a fresh minimal-pair speech risk (gender/
number agreement suffixes are exactly the class `frSpeechMinimalPairs.test.ts`
already treats as highest-risk). No payoff argument for m23 specifically:
this is a substantial grammar beat with real new machinery cost and a
genuinely new speech-risk class, better suited to its own dedicated module
with its own bespoke speech probe than folded into this cycle's decision.
Rejected for m23, not for the course — a real future candidate once a
module can afford a dedicated speech-probe script for it.

### 1.7 Time-telling («il est deux heures») — PICKED

Re-verified from scratch, going beyond any prior FR brief's depth on this
candidate because it has been implicitly available and un-picked since at
least m17 (numbers) and m21 (hundreds/mille) shipped, and the task
specifically asks why:

- **Two tease lines already sit in the course, unresolved, both in `m2.ts`**
  (grep-verified, exact lines): `"Quelle heure est-il ?"` (kana + audioText,
  `m2.ts:327-328`) and `"Vous avez l'heure ?"` (`m2.ts:454-455`). Both are
  m2's own deliberate "incomprehensible now, promise for later" teases
  (§13.6 pattern, same class as m2's other early promises the course has
  since cashed one by one).
- **Neither tease line is literally authorable yet, and this is a genuine
  finding, not a rubber stamp:** `"Quelle heure est-il ?"` needs verb-subject
  INVERSION (`est-il`), a syntax the course has never taught anywhere —
  grep across every `m*.ts` confirms zero occurrences of `est-il`,
  `est-elle`, `a-t-il`, `va-t-il`, or `est-ce que` outside m2's own tease
  and one brief-prose mention (m19's header, discussing why it avoided
  `qu'est-ce que`). `"Vous avez l'heure ?"` needs `vous` as CONTENT, blocked
  per §1.2. **Neither of m2's own promised question forms can be cashed
  literally in m23** — this has to be stated plainly rather than silently
  worked around, because it changes what m23 can promise: it teaches
  time-telling, but it answers m2's tease by REPLACING its question form,
  not reproducing it.
- **The replacement is well-precedented, not invented for this brief:** the
  course's established safe question pattern is wh-word-in-situ, no
  inversion — `"tu vas où ?"` (m5, recalled through m6/m7/m8/m9/m11/m13/m16)
  and `"tu habites où ?"` (m11). The parallel construction `"il est quelle
  heure ?"` (literally "it is what hour?", word-for-word in-situ) uses only
  already-chrome `quelle` (`FR_FUNCTION_WORDS`, confirmed present:
  `"quand comment pourquoi combien quel quelle quels quelles"`) and already-
  taught `il est` (§1.7.1 below) — zero new syntax, same shape as the
  course's own established question pattern. This is the house "same
  chrome, new job" move (m18/m19/m20/m22's shared pattern) applied to a
  question form instead of a statement.
- **§1.7.1 — the dummy/impersonal-`il` bridge is already built, twice over:**
  `il y a` (m4, "there is/are") already establishes impersonal `il` as a
  dummy subject with no real-world referent — direct precedent for
  `il est deux heures` ("it is two o'clock," no referent either).
  Separately, REFERENTIAL `il est` (he/it is — `"il est très grand"`,
  `"il est très petit"`, m10) is already taught and recalled. The bridge
  card m23 needs is exactly the m18/m19/m20/m22 house pattern: quote m10's
  own `"il est très grand"` card side-by-side with the new
  `"il est deux heures"`, showing the same two words doing a different
  job — dummy subject, not "he." This is a stronger, cleaner bridge than
  any prior module's needed (m18 negation, m19 aller, m20 venir, m22
  de-possession all had exactly one precedent card to lean on; this one has
  two independent precedents converging on the same construction).
- **The number machine is fully in place and needs nothing new:** m1
  (0–20 digits), m12 (tens/vingt), m17 (teens 11–16 + irregular 70–99),
  m21 (hundreds/mille) collectively cover every number time-telling needs
  (1–12 for the hour, with round numbers only — no minutes-past/-to in
  scope, §3). Zero new number atoms required.
- **Cost is low and well-precedented:** exactly 2 new atoms, `heure`/
  `heures` — the SAME registration shape as m12's `euro`/`euros` (separate
  singular/plural noun atoms, no automatic pluralization in this course,
  confirmed precedent also at m3's chat/chats and m10's livre/livres) and
  the same silent-plural-s homophone shape the course already has a
  verified-safe answer for (§6).
- **This is a real forcing function**, not an arbitrary pick: it is the
  only candidate among the six that (a) directly cashes a specific,
  named, still-open promise from m2 rather than opening a new one, (b)
  needs zero new grammatical machinery beyond a bridge card over two
  already-independently-precedented constructions, (c) needs a minimal,
  cheaply-priced atom set with an exact precedent for cost, and (d)
  introduces no new speech-risk CLASS (§6) — the standing gate already
  covers its risk shape.

## 2. Module thesis (design authority for this dispatch)

**m23 teaches telling time on the hour**, using ONLY machinery the course
already owns: the dummy-`il` + `être` construction (`il y a` precedent, m4)
recombined with the REFERENTIAL `il est` the learner already has (m10),
recombined with the number machine (m1/m12/m17/m21), to produce and
recognize `"il est deux heures"` / `"il est une heure"` (singular exception
— `une heure`, not `un heure`/`unes heures`, gender-matching `heure` as
feminine) and answer/ask with the wh-in-situ pattern `"il est quelle
heure ?"` (§1.7, replacing rather than reproducing m2's inversion tease).

The teaching claim to state explicitly in the module header (paste-ready):
"You already have «il est» — you've used it for people and things
(«il est très grand»). Watch it do a completely different job: no one it's
pointing at, just announcing the time. And the numbers? Already yours —
«il est deux heures» is «il est» plus a number you've known since m1, plus
one new little word for what you're counting."

This is the house "same chrome, new job" pattern (m18 ne...pas→jamais/
rien/plus, m19 aller→near future, m20 venir→recent past, m22 de:origin→
possession) applied a fifth time, this time to `il est` specifically
(referential→impersonal) rather than to a preposition or negator — and
it is the first m17+ module whose bridge card can point at TWO independent
prior precedents (`il y a` for the dummy-subject move, `il est` itself for
the exact words) rather than one.

**Explicitly OUT OF SCOPE for m23** (state these, don't silently omit —
each is a real future candidate, not a rejected idea):
- Minutes past/to the hour (`et quart`, `et demie`, `moins le quart`) —
  needs new atoms (quart, demi/demie) and non-trivial new arithmetic-in-
  language; a natural m24+ extension once m23's on-the-hour foundation is
  live.
- `midi`/`minuit` (noon/midnight, irregular — no `heure(s)` word at all)
  — a small, cheap, well-scoped follow-on addition once the base
  construction is proven; deliberately deferred to keep m23's atom count
  minimal and its teaching claim singular.
- Genuine inversion syntax (`est-il`, `a-t-il`) — still blocked course-wide
  (§1.7); not attempted here or anywhere yet.
- `vous avez l'heure ?` as a literal recall of m2's second tease — still
  blocked by `vous` (§1.2); m23 answers m2's THEME (asking/telling time),
  not its literal sentence.

- **L3 — The one irregular agreement.** `une heure` vs `deux heures` —

- **L6 — Recall.** Cross-module recall lesson, ≥1 recall each from m4

## 5. Homophone / liaison risks

- **`heure`/`heures` is a silent-h (h muet) word** — elides and liaises
  normally, unlike m17's `onze`/m1's `huit` (h aspiré-flagged consonant-
  onset words). `"l'heure"` (elided, correct) and `"deux heures"` (liaison
  /dø.zœʁ/, the -s surfaces as /z/) are both standard, expected forms — no
  special `consonantOnset` flag needed on these atoms (contrast onze,
  §m17's mechanism). Playbook §6 records h-aspiré as "resolved m15" — this
  module adds an h-muet instance to the same machinery, not a new case.
- **Silent plural -s homophone:** `heure`/`heures` sound identical in
  isolation (the liaison /z/ only appears before a following vowel-onset
  word, not lesson-final) — same shape as `euro`/`euros` (m12) and `cent`/
  `cents` (m21), both of which already carry a `homophoneKey` on the
  registered atom. Recommend the same treatment: give `heures` a
  `homophoneKey` matching `heure`'s pronunciation, per the euro/euros
  precedent (`m12.ts:99`, `homophoneKey: "øʁo"`).
- **`une` vs `un` (L3's whole point)** is a minimal PAIR by design, not a
  risk to avoid — it must never be the sole content of a `speaking` step
  (§6) but is exactly the kind of contrast `sentenceMcq`/`cloze` exist to
  grade safely.
- No d'-elision content in this module (heure is h-muet, not vowel-onset in
  the d'-blocking sense — `de l'heure` would elide fine if ever needed, but
  nothing in this module's scope calls for a `de` + heure construction).

## 6. TTS / speech-grading notes

- **No bespoke probe script recommended.** This module's speech risks
  decompose into two already-solved classes:
  1. The `heure`/`heures` silent-plural-s homophone — same shape as
     `euro`/`euros` and `cent`/`cents`, already exercised by
     `ROMANCE_ROUND_HUNDREDS_WORDS`/`foldRoundHundreds()` and the general
     number-word folding tables in `loose-match.ts`; no new matcher
     behavior needed, only the same `homophoneKey` registration pattern
     (§5).
  2. `une heure` vs `deux heures` — a gender/number minimal pair, the
     exact class `frSpeechMinimalPairs.test.ts` already generalizes over
     course-wide. Design around it the same way m22 did: no `speaking`
     step is the sole graded checkpoint discriminating `une` from a
     numbered form — that discrimination lives in cloze/sentence-MCQ
     (§4 L3), matching the task's own binding constraint and the m18/m19/
     m20/m22 doctrine.
- **Design rule, paste verbatim into the module header:** every `speaking`
  step in this module targets a full time statement already resolved
  earlier in the same lesson (recall-only or first-non-recall voicing of
  a SEEN sentence) — never a live "what time is it" guess where the
  correct hour must be freshly discriminated from a sibling by voice
  alone.
- Standard TTS chain (playbook §4) applies unchanged. New strings: every
  composed time sentence actually used in content (not a padded 1–12 ×
  every-frame combinatorial list). Verify with the standard chain after
  authoring — the emitter is regex-based and skips silently on an
  unmatched shape (CLAUDE.md TTS section).

## Speech probe wanted: NO (standing gate suffices)

No bespoke `frSpeechHundreds.test.ts`-style script is warranted. Unlike
m21 (which found a genuinely NEW risk class — digit-transcript-array
overflow — requiring its own probe), m23's speech risks are both members
of risk classes the course already has verified, working answers for:

1. **Silent-plural-s homophones** (`heure`/`heures`) — identical shape to
   `euro`/`euros` (m12) and `cent`/`cents` (m21), both already documented
   in `docs/fr-speech-hundreds-2026-09-10.md` as "unfixable-by-design, work
   around in content, not the matcher" — the answer is the same
   `homophoneKey` + never-sole-graded-speaking-target pattern, not a new
   finding.
2. **Gender/number minimal pairs** (`une heure`/`deux heures`) — exactly
