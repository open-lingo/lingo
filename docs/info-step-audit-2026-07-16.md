## Methodology

Every `infoStep(id, title, body, variant?)` call and literal `{ type: "info", ... }` object across all 46 curriculum files was extracted with a bracket-aware parser (handles multi-line bodies, `+`-concatenation, nested arrays) that also counts each lesson's total step count, so every info step's ordinal position is known exactly. "First step" / "last step" / "mid" below is derived from that, not eyeballed.

Category (c) candidates were then cross-checked against whether their *own lesson* also contains a `grammar_rule` step (inline `grammarRule(...)` or a bare reference to a `const X = grammarRule(...)`) elsewhere in the same `steps[]` array. If a proper grammar_rule card already exists in-lesson, the info card is a redundant teaser (category b), not a wrong-vehicle problem — this cut the initial ~103 keyword-matched candidates down to a defensible 20.

## 1. The structural pattern (why this is 3 buckets, not 862 snowflakes)

862 is misleading on its own — the curriculum is extremely formulaic. Virtually every sub-lesson (m3–m27) is built as **`infoStep(open) → exercises → infoStep(end, variant="win")`**, generated by a shared `infoStep()` helper (`src/features/languages/ja/grammarHelpers.ts:196`). 742 of 862 steps (86%) are exactly these open/end pairs; only 19 sit mid-lesson.

| Position | Count | Avg. word count | What it typically is |

| Mid-lesson | 19 | 27.6 words | Either a real concept aside, a "real-world phrase" culture note, or a "tap the mic" speaking tip |

## 6. Recommendation for category (c)

Three options, per the task brief:

| Option | Mechanism | Fit here |
|---|---|---|
| **1. Hoist into a module/level header, shown once** | `CourseModule.summary` (already exists, `src/shared/domain/course.ts:44`; already populated for all ja modules in `mockCourse.ts`; already rendered once on the course-map "selected module" panel, `CourseMapPage.tsx:306-309`) | Works only for the ~5 items that are genuinely module-opening scene-setters (Katakana intro, Numbers intro, Dakuten intro, Yōon intro, citation form). Doesn't fit the other 15, which are mid-module asides tied to one specific sub-lesson, not the whole module. `summary` is also a single short line today — not built for a rule + example. |
| **2. Convert to `grammar_rule` (compact variant)** | `GrammarRuleStep` type already exists (`types.ts:400`); the `compact` variant already exists purpose-built for exactly this ("small pane, title + rule + first example only" — `GrammarRuleStepView.tsx:14-18`); **the lesson runner already renders every `grammar_rule` step as `compact` by default** as of Workshop A, 2026-07-12 (`StepRenderer.tsx:171-182`, "the monolith full treatment is retired from the learner path") | Fits all 20. Gets the read-gate timer (forces the card to actually be read, unlike a skippable info card — directly answers the owner's "people will just skip past them"), structured `rule` + `examples` fields instead of a prose blob, and is consistent with the very recent design direction for this exact problem (grammar_rule was itself just redesigned to be lighter-weight). |
| **3. Merge into the first exercise as a lead-in** | No existing mechanism — would need new UI (a subtitle/hint slot on `build`/`cloze`/`vocabMcq` step views) | Highest code cost, no precedent, and grammar_rule already solves the "too heavy" problem option 3 is trying to avoid. Not recommended. |

**Recommended: Option 2 (convert to `grammar_rule`, compact variant) for all 20.** It requires zero new component work, is already the default rendering path, and is the more rigorous vehicle (structured rule/example/anti-pattern fields + enforced read-gate) for content the owner has already called "necessary." For the ~5 items that double as module-opening framing (Katakana intro, Numbers intro, m2-g Dakuten intro, m2-yoon-intro, m7 citation form), optionally *also* fold a one-line distillation into that module's existing `summary` field (Option 1) — cheap, additive, not a replacement.
