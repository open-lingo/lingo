## 0. What m41 teaches (from spine-n4.md, corrected below)

- **〜てある**: a 他動詞 (transitive verb) with the を→が flip, describing a
  STATE someone left on purpose — まどが あけてある ("the window has been
  left open [by someone, on purpose]"), contrast まどが あいている ("the
  window is open" — no claim about who or why).
- **THE SPINE MODULE — one minimal pair, not a grammar point in isolation:**
  まどが あいている (自動詞 + ている, m33) vs まどが あけてある (他動詞 +
  てある). Same English translation, different claim: ている describes a
  state with no comment on intention; てある asserts somebody did it on
  purpose and the result persists. This pair is the entire teaching object
  of the module's first half — spend the lessons on it, not on a vocabulary
  list.
- **〜ておく (m30) vs 〜てある — the second beat, same-module pairing named by
  the spine.** ておく is prospective ("I'll leave it done, in preparation");
  てある is the retrospective state that prep produced ("it has been left
  done"). まどを あけておく ("I'll leave the window open [for later]") →
  まどが あけてある ("the window has been left open [now, as a result]").
  Same helper-verb schema (て + known verb) both directions, which is why
  m30's own file-level comment (`m30-neo.ts` line ~9) already flags m41 as
  where てある pays off — this is not a new idea to the codebase, it is a
  forward reference m30 already made good on.
- **MORPHOLOGICAL-FAMILY NOTICING over the pairs already owned (see §1 —
  NINE, not the spine's stated six) plus new pairs this module adds — as
  PATTERN-NOTICING, explicitly NOT a table.** The spine names three shape
  families: -aru/-eru (あく/あける), -ru/-su (でる/だす), -eru/-asu
  (おちる/おとす — already in m33's set, see §1). This is a "notice the
  shape" beat threaded across 1-2 lessons, never a single block lesson that
  lists all pairs — m33's own `why` text names the table itself as "the
  wall," and the drip thread (`thr-n4`) reinforces: pairs arrive with the
  domain that needs them, never as a set to memorize.
- **⟳ deepen of n4-04 (m33)** — this is a BACKWARD spiral, eight modules on
  (m33 → m41), matching thr-n4's "≥4 modules apart" spiral-spacing rule
  with room to spare. m33's compiled lessons/atoms are a real, existing
  pull-source for review pools (unlike m40's forward-only spiralWith to
  n4-16).
- **spiralWith: n4-04 (m33).** Realize this concretely in m41's review
  lessons by pulling m33's nine pairs into the review pool alongside m41's
  new ones — mirrors how m39 realized its `spiralWith: m16` (§4 below).

**why (spine's own words):** "The transitivity deepen beat, and deliberately
AFTER passive rather than before. てある and the passive both promote a
non-agent into the が slot; once the passive frame is owned, ている / てある
/ られる can be taught as ONE coherent three-way contrast instead of three
unrelated tricks learned months apart. This ordering is the reason the

## 2. Engineering: does the compiler/engine already support 〜てある?

**Verified 2026-09-10 — settles the brief's core engineering question: NO
new engine work is required. てある is compositional, not a formation
point, and follows the m30 (ておく)/m38 (てしまう) precedent exactly, NOT
the m40 (passive) precedent.**

- `conjugationEngine.ts`'s `ChainForm` type (the exhaustive list of
  morphological transforms the engine knows how to derive) has **no
  `"aru"` or `"te-aru"` member** — confirmed by direct read of the type
  (`masu | masu-neg | ... | volitional | ba | potential | tara | imperative
  | prohibitive | causative | passive`). Nothing was added for this module
  because nothing needs to be: てある is not a new conjugation of the base
  verb, it is [base verb]-て (already a live `ChainForm`, "te," since M8) +
  ある used as a helper verb in its own right.
- `TRANSFORM_RULESETS` (`conjugation/transformRulesets.ts`) currently has
  **exactly 5 entries — `nai`, `masu`, `te`, `volitional`, `ba`** (confirmed
  by direct grep, 2026-09-10; matches m40's brief's own count before m40
  adds `passive` as its 6th). Neither `te-oku` (m30) nor `te-shimau` (m38)
  ever added an entry, despite both being "te + helper verb" constructions
  exactly like てある. **m41 should not add one either.**
- `docs/authoring-invariants-pinned.md` inv 49 requires a `TRANSFORM_
  RULESETS` entry for a "formation point" — its own definition names the
  closed list this applies to: **て, た, ない, ます, potential, passive
  られる, causative させる, volitional よう/おう, ば, 命令形/禁止形.** てある
  is NOT in this list. Inv 49's separate "why it is pinned" rationale
  paragraph does mention てある (m41) alongside passive/causative in a
  looser enumeration of "N4 is formation-dense" — **this brief's
  determination is that the rationale paragraph is describing the general
  wave of N4 て+helper/voice content loosely, not expanding inv 49's own
  stated definitional list; てある is compositional (known て-form + a known
  helper verb, ある, already taught since m6), the same category as m30's
  ておく and m38's てしまう, neither of which triggered inv 49 in practice.**
  If a future gate or reviewer disagrees, the fix is a one-line
  `TRANSFORM_RULESETS["te-aru"]` addition mirroring m40's `passive` entry —
  cheap to add later, not worth blocking dispatch over a reading of a
  rationale sentence.
- **ある itself has no row in `conjugationTables.ts`'s `VERB_ENTRIES`**
  (confirmed by grep — only あるく "to walk" appears, an unrelated
  homograph-adjacent word sharing the ある- prefix, not a token collision
  since JA tokenization matches whole dictionary entries, not substrings —
  see §4). ある's own inflected forms needed for this module (ある, あった,
  ない/ありません) must be **hand-authored as `kind: verb-form,
  derivedFrom: ある` newAtoms**, exactly the pattern m30 used for
  `おく`/`おいた` (`ir/m30.ir.yaml` lines ~454-455: `おく` registered as a
  plain `kind: verb` atom, `おいた` as a `verb-form` derived from it, no
  engine involvement). Do the same for ある/あった/(ない or ありません, per
  register) here.
- **courseAtoms already has an `id: "aru"` row** (kana ある, fromModule m6,
  blocked:true, "existence-of — rubric explicit block", `conjugation:
  {class: "godan"}`). Per the m40 brief's own established precedent for
  blocked-but-known words (こわす, blocked:true, still usable as a known
  carrier), **ある is usable as a known helper verb in てある constructions

**Net determination: m41 needs NO changes to `ChainForm`, NO new
